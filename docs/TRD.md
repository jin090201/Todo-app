# TRD - Todo 앱 (초안)

> 기준 문서: docs/PRD.md, docs/IDEA.md, 프로젝트 규칙 문서(CLAUDE.md)
> 상태: 초안. PRD의 "결정이 필요한 것"은 이 문서에서도 정하지 않고 **미결정**으로 표시합니다.
> API 경로, 응답 형식, 테이블 구조의 자세한 내용은 docs/API_SPEC.md, docs/DATA_MODEL.md에서 확정합니다. 이 문서에 나오는 예시는 이해를 돕기 위한 것입니다.

## 1. 목적
- PRD에 적힌 기능(F-01 ~ F-05)을 **어떤 기술로, 어떤 구조로** 만들지 정리한다.
- 각 기술을 왜 골랐는지 초보자도 이해할 수 있게 적는다.
- 화면에서 버튼을 누른 뒤 DB에 저장되기까지의 흐름을 단계별로 보여준다.

## 2. 기술 스택과 고른 이유

### 2-1. 프론트엔드 (화면)
| 기술 | 역할 | 왜 골랐나 (한 줄 설명) |
|------|------|------------------------|
| Next.js 15 (App Router) | 화면 뼈대 | 페이지를 만들고 실행하는 도구가 다 들어 있고, `/api` 요청을 백엔드 서버로 넘겨 주는 기능(rewrites)이 있어서 화면 코드는 같은 주소로만 요청하면 된다. |
| React 19 | 화면 만들기 | 화면을 "컴포넌트"라는 작은 조각으로 나눠 만들고, 데이터가 바뀌면 화면이 알아서 다시 그려진다. |
| TypeScript (strict) | 화면 쪽 언어 | 변수에 "이건 문자열, 이건 숫자"처럼 타입을 붙여서, 실행하기 전에 실수를 미리 잡아 준다. |
| Tailwind CSS | 화면 꾸미기 | `p-4`, `text-red-500` 같은 짧은 이름을 붙이기만 하면 돼서 CSS 파일을 따로 관리하지 않아도 된다. |
| Zod | 화면 입력값 검사 | "제목은 1~100자" 같은 규칙을 코드 한 곳에 적어 두고, 서버에 보내기 전에 화면에서 먼저 걸러 낸다. |
| Jest + React Testing Library | 화면 테스트 | 사용자가 실제로 입력하고 버튼을 누르는 것처럼 화면을 자동으로 테스트할 수 있다. |

### 2-2. 백엔드 (API 서버, v0.2부터)
| 기술 | 역할 | 왜 골랐나 (한 줄 설명) |
|------|------|------------------------|
| Python 3.12 이상 | 서버 쪽 언어 | 문법이 짧고 읽기 쉬워서 초보자가 서버 코드를 이해하기 좋다. |
| FastAPI | API 서버 | 함수 위에 `@app.get("/api/todos")`처럼 한 줄만 붙이면 API가 되고, 타입 힌트만 적어 두면 요청 검사와 API 문서(`/docs`)를 자동으로 만들어 준다. |
| Uvicorn | 서버 실행기 | FastAPI 앱을 실제로 켜서 요청을 받게 해 주는 프로그램이고, `--reload`로 코드를 고치면 자동으로 다시 켜진다. |
| Pydantic | 서버 입력값 검사 | FastAPI에 들어 있는 검사 도구로, 요청 JSON이 규칙에 맞는지 클래스 하나로 정의해 검사한다. (화면의 Zod와 같은 역할) |
| regex | 글자 수 세기 | 파이썬 기본 `len()`은 이모지 "👍🏻"를 2자로 세서, 눈에 보이는 글자 단위(`\X`)로 셀 수 있는 이 라이브러리를 쓴다. |
| pytest (+ FastAPI TestClient) | 서버 테스트 | 서버를 실제로 켜지 않고도 API에 요청을 보내 보고 응답을 확인할 수 있다. |

### 2-3. 데이터베이스 (v0.3부터)
| 기술 | 역할 | 왜 골랐나 (한 줄 설명) |
|------|------|------------------------|
| PostgreSQL | 데이터베이스 | 서버를 껐다 켜도 할 일이 남도록 저장하는 곳이고, UUID 타입과 `RETURNING`(저장한 행을 바로 돌려받기)처럼 이 앱에 필요한 기능을 기본으로 갖고 있다. |
| psycopg 3 | DB 접속 드라이버 | 파이썬에서 PostgreSQL에 접속해 SQL을 보내는 표준 라이브러리이고, ORM 없이 SQL을 직접 써서 DB가 실제로 어떻게 동작하는지 배울 수 있다. |

## 3. 전체 구조

```
[브라우저]                [Next.js 개발 서버 :3000]          [FastAPI 서버 :8000]                 [DB]
 화면 컴포넌트 ── fetch ──▶ /api/* 요청을 그대로 넘김 ──────▶ 라우터 (backend/app/...)
 (src/components)          (next.config.ts rewrites)          │
       ▲                                                      ▼
       │                                            Pydantic 검사 → 저장 로직 ── psycopg (SQL) ──▶ PostgreSQL
       └──────────────────────────── JSON 응답 ◀──────────────────────────────────────────────────┘
```

- 화면은 항상 `/api/todos`처럼 **자기 주소**로 요청한다. Next.js가 이 요청을 FastAPI(`http://localhost:8000`)로 넘겨 준다.
  - 이렇게 하면 브라우저 입장에서는 같은 주소로 요청하는 것이라 CORS(다른 주소로 요청할 때 브라우저가 막는 규칙) 설정이 필요 없다.
- FastAPI 주소는 코드에 직접 쓰지 않고 환경 변수(`BACKEND_URL`)로 둔다.

### 폴더별 역할
| 폴더 | 들어가는 것 |
|------|-------------|
| app/ | 페이지 (API 라우트는 만들지 않음) |
| src/components/ | 화면 컴포넌트 (입력창, 목록, 할 일 한 줄 등) |
| src/lib/ | 화면 쪽 공통 로직 (Zod 스키마, API 호출 함수) |
| src/types/ | 화면 쪽 타입 (예: Todo) |
| tests/ | 화면 테스트 (Jest). `src/`와 같은 폴더 구조로 둔다 |
| backend/app/ | FastAPI 서버 코드 (라우터, Pydantic 모델, 저장 로직) |
| backend/sql/ | 테이블 생성 SQL (v0.3부터) |
| backend/tests/ | 서버 테스트 (pytest) |
| docs/ | 명세 문서 |

## 5. 버튼을 누른 뒤 DB에 저장되기까지의 흐름 (F-01 할 일 추가, v0.3 기준)

사용자가 입력창에 "우유 사기"를 적고 **추가** 버튼을 누른 상황입니다.

| 단계 | 어디서 | 무슨 일이 일어나나 |
|------|--------|--------------------|
| 1 | 브라우저 (화면 컴포넌트) | 사용자가 입력창에 제목을 적는다. React가 입력값을 상태(state)에 담아 둔다. |
| 2 | 브라우저 (화면 컴포넌트) | 사용자가 **추가** 버튼을 누르면 버튼에 연결된 함수(이벤트 핸들러)가 실행된다. |
| 3 | 브라우저 (Zod) | 앞뒤 공백을 지운 제목이 1~100자인지 먼저 검사한다. 틀리면 서버에 보내지 않고 화면에 이유를 보여준 뒤 멈춘다. |
| 4 | 브라우저 → Next.js | `fetch`로 `POST /api/todos`에 요청을 보낸다. 제목은 JSON으로 담아 보낸다. (`{ "title": "우유 사기" }`) |
| 5 | Next.js → FastAPI | Next.js가 이 요청을 그대로 FastAPI 서버(`:8000`)로 넘긴다. |
| 6 | FastAPI (Pydantic) | 같은 규칙으로 **한 번 더** 검사한다. 브라우저 검사는 우회될 수 있으므로 서버 검사가 진짜 관문이다. 틀리면 실패 응답을 돌려준다. |
| 7 | FastAPI (저장 로직) | 검사를 통과한(공백을 지운) 제목으로 "할 일 추가" 함수를 부른다. |
| 8 | FastAPI (psycopg) | `INSERT INTO todos (title) VALUES (%s) RETURNING ...` SQL을 DB에 보낸다. 값은 `%s` 자리에 따로 넘겨서, 제목에 이상한 문자가 들어 있어도 SQL이 깨지지 않게 한다(SQL 인젝션 방지). |
| 9 | DB (PostgreSQL) | 새 행을 저장한다. id, 완료 여부(기본값: 미완료), 만든 시각은 DB가 채운다. `RETURNING` 덕분에 저장한 행을 바로 돌려준다. |
| 10 | FastAPI → Next.js → 브라우저 | 저장된 할 일을 JSON으로 응답한다. Next.js는 받은 응답을 그대로 브라우저에 전달한다. |
| 11 | 브라우저 (화면 컴포넌트) | 응답받은 할 일을 목록 상태의 **맨 위**에 넣는다(최신순, F-02). 입력창을 비운다. |
| 12 | 브라우저 (React) | 상태가 바뀌었으므로 React가 목록을 다시 그린다. 사용자는 새 할 일을 바로 본다. |

### 실패하면?
- **검사 실패 (3, 6단계)**: 할 일을 저장하지 않고 사용자에게 이유를 보여준다. (PRD 사용자 스토리 F-01)
- **서버나 DB 오류 (7~10단계)**: 목록에 추가하지 않고 "저장하지 못했다"는 메시지를 보여준다.
- **FastAPI 서버가 꺼져 있음 (5단계)**: Next.js가 요청을 넘기지 못해 에러 형식이 아닌 500 응답을 돌려준다. 화면은 "잠시 후 다시 시도해 주세요."를 보여준다. (COMPONENT_SPEC 4장 "응답이 에러 형식이 아님")
  - "서버에 연결할 수 없습니다" 문구는 Next.js 서버까지 꺼져 있어서 `fetch` 자체가 실패할 때만 나온다.
- 응답 코드와 오류 메시지 형식은 docs/API_SPEC.md에서 정한다.

### 버전마다 달라지는 부분
- **v0.1**: 4~10단계가 없다. 3단계 검사를 통과하면 바로 11단계로 가서 브라우저 상태에만 넣는다.
- **v0.2**: 8~9단계 대신 FastAPI 메모리의 리스트에 넣는다. id와 만든 시각은 FastAPI가 만든다. 나머지는 같다.
- **v0.3 이후**: 위 표 그대로.

### 다른 기능도 같은 모양으로 흐른다
| 기능 | 버튼/동작 | 서버에서 하는 일 |
|------|-----------|------------------|
| F-02 목록 보기 | 페이지 열기 | DB에서 만든 시각 기준 최신순으로 읽어 온다. 완료 여부로는 정렬하지 않는다. |
| F-03 완료 전환 | 체크박스 누르기 | 화면이 바꿀 값을 직접 보낸다(예: `PATCH /api/todos/{id}`, `{ "completed": true }`). 서버는 받은 값 그대로 저장한다. |
| F-04 삭제 | 삭제 버튼 누르기 | 해당 할 일을 DB에서 지운다. (삭제 확인 창 여부 **미결정**) |

## 6. 입력값 검사 (Zod + Pydantic)
- 같은 규칙을 **화면(Zod)과 서버(Pydantic) 두 곳**에 적는다. 언어가 달라서 코드를 함께 쓸 수 없기 때문이다.
  - 두 규칙이 서로 달라지지 않도록, 같은 경계값 목록(TEST_CASES)으로 양쪽을 모두 테스트한다.
  - 진짜 관문은 서버(Pydantic)다. 화면 검사는 사용자에게 빨리 알려 주기 위한 것이다.
- 앞뒤 공백을 지운 뒤 길이를 센다. 저장도 공백을 지운 제목으로 한다.
- 글자 수는 눈에 보이는 글자 하나를 1자로 센다.
  - 화면: 브라우저에 들어 있는 `Intl.Segmenter`로 센다. 그냥 `.length`를 쓰면 "👍🏻"가 4자가 된다.
  - 서버: `regex` 라이브러리의 `\X`로 센다. 그냥 `len()`을 쓰면 "👍🏻"가 2자가 된다.
- 경계값: 0자 실패, 1자 성공, 100자 성공, 101자 실패, 공백만 입력하면 실패. (PRD 7. 성공 기준)

### 완료 전환을 "값 보내기"로 정한 이유
- "반대로 바꿔" 방식은 같은 요청이 두 번 가면 원래대로 돌아가 버린다. 바꿀 값을 직접 보내면 두 번 보내도 결과가 같다.
- v0.4의 "수정" 기능도 같은 PATCH 요청에 `title`만 더하면 된다.

## 7. 테스트 방침
- 화면 (Jest + React Testing Library)
  - Zod 스키마: 경계값을 단위 테스트로 확인한다.
  - 화면 컴포넌트: 입력 → 버튼 클릭 → 목록에 보이는지 확인한다.
- 서버 (pytest + FastAPI TestClient)
  - Pydantic 모델: 화면과 같은 경계값을 확인한다.
  - API: 추가, 목록, 완료 전환, 삭제가 명세대로 동작하는지 확인한다.
- 테스트를 삭제하거나 skip하지 않는다. 실패하면 구현 코드를 고친다.
- 자세한 테스트 목록은 docs/TEST_CASES.md에서 정한다.

## 8. 코딩 규칙 (기술 관련)
- TypeScript strict 모드를 켜고 `any` 타입을 쓰지 않는다.
- Python 코드에는 함수 인자와 반환값에 타입 힌트를 붙이고, `Any` 타입을 쓰지 않는다.
- 주석은 초보자가 이해할 수 있게 한국어로 짧게 쓴다.
- `console.log`(TypeScript), `print`(Python)는 디버깅 후 지운다.
- SQL에 값을 넣을 때는 문자열을 이어 붙이지 않고 항상 `%s` 자리표시자를 쓴다.
- Python 패키지는 `backend/.venv` 가상환경에 설치하고, 목록은 `backend/requirements.txt`에 적는다. `.venv`는 git에 올리지 않는다.
- DB 접속 주소(`DATABASE_URL`), 백엔드 주소(`BACKEND_URL`) 같은 값은 코드에 직접 쓰지 않고 환경 변수 파일(`.env`, `.env.local`)에 두며, 이 파일들은 git에 올리지 않는다.
