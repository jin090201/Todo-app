# PRD - Todo 앱 (초안)

> 기준 문서: docs/IDEA.md
> 상태: 초안. "결정이 필요한 것"에 있는 항목은 아직 정하지 않았습니다.

## 1. 목표
- 혼자 쓰는 간단한 할 일 목록 웹 앱을 만든다.
- 할 일을 적고, 끝낸 일을 체크하고, 필요 없는 일을 지우는 것까지만 한다.
- 새로고침해도 적어 둔 할 일이 사라지지 않게 한다.

## 2. 대상 사용자
- 사용자는 한 명(본인)뿐이다.
- 여러 사람이 함께 쓰거나 다른 사람과 공유하는 상황은 생각하지 않는다.

## 3. 기능 목록 (MVP)

| ID | 기능 | 설명 |
|------|------|------|
| F-01 | 할 일 추가 | 제목을 입력해 할 일을 추가한다. 제목은 꼭 있어야 하고 1~100자여야 한다. 앞뒤 공백을 지운 뒤, 눈에 보이는 글자 하나를 1자로 센다. |
| F-02 | 할 일 목록 보기 | 추가한 할 일을 최신순(가장 최근에 추가한 것이 위)으로 보여준다. 완료한 항목도 자리를 옮기지 않고 같은 순서를 따른다. |
| F-03 | 완료/미완료 전환 | 체크박스를 눌러 할 일을 완료나 미완료로 바꾼다. |
| F-04 | 할 일 삭제 | 할 일을 목록에서 지운다. |
| F-05 | 데이터 유지 | 페이지를 새로고침해도 할 일 목록이 그대로 남아 있다. 버전마다 지키는 정도가 다르다. ("4. 버전별 데이터 유지" 참고) |

## 4. 버전별 데이터 유지

IDEA.md의 버전 로드맵에 적힌 저장 위치를 기준으로, 버전마다 할 일이 언제 남고 언제 사라지는지 정리한 표입니다.

| 버전 | 데이터 저장 위치 | 새로고침하면 | 서버를 껐다 켜면 | F-05 충족 |
|------|------------------|--------------|------------------|-----------|
| v0.1 | 브라우저 메모리 | 사라짐 (localStorage를 쓰면 남음, **미결정**) | 해당 없음 (서버에 저장하지 않음) | 미결정 |
| v0.2 | 서버 메모리 | 남음 | 사라짐 | 일부 (새로고침만) |
| v0.3 | DB | 남음 | 남음 | 충족 |
| v0.4 | DB | 남음 | 남음 | 충족 |
| v1.0 | DB (배포 환경) | 남음 | 남음 | 충족 |

- **브라우저 메모리**: 지금 열어 둔 페이지 안에만 데이터를 들고 있는 것. 페이지를 새로 불러오면 처음 상태로 돌아간다.
- **localStorage**: 브라우저 안에 데이터를 저장해 두는 공간. 새로고침해도 남지만, 그 브라우저에서만 보인다.
- **서버 메모리**: 서버 프로그램이 켜져 있는 동안만 데이터를 들고 있는 것. 서버를 끄면 사라진다.
- **DB**: 데이터를 파일처럼 오래 저장해 두는 곳. 서버를 껐다 켜도 남는다.

## 5. 사용자 스토리
- F-01: 사용자로서, 해야 할 일을 잊지 않도록 제목을 적어서 목록에 추가하고 싶다.
- F-01: 사용자로서, 실수로 빈 제목이나 너무 긴 제목을 입력하면 추가되지 않고 그 이유를 알고 싶다.
- F-02: 사용자로서, 가장 최근에 추가한 일을 먼저 보고 싶다.
- F-03: 사용자로서, 끝낸 일을 체크해서 남은 일과 구분하고 싶다.
- F-03: 사용자로서, 잘못 체크한 일을 다시 미완료로 되돌리고 싶다.
- F-04: 사용자로서, 더 이상 필요 없는 일을 목록에서 지우고 싶다.
- F-05: 사용자로서, 새로고침을 해도 적어 둔 할 일이 사라지지 않았으면 좋겠다.

## 6. 범위 밖

### 만들지 않는 것
- 로그인
- 공유
- 알림
- 마감일
- 카테고리

### 나중 버전에서 만드는 것 (MVP에는 넣지 않음)
- 할 일 수정 (v0.4)
- 필터 (v0.4)
- 배포 (v1.0)

## 7. 성공 기준
- F-01 ~ F-04가 모두 설명대로 동작한다.
- 제목 길이 검사가 경계값에서 맞게 동작한다.
  - 0자(빈 제목): 추가되지 않는다.
  - 1자, 100자: 추가된다.
  - 101자: 추가되지 않는다.
  - 공백만 입력: 추가되지 않는다. (앞뒤 공백을 지우면 0자)
  - 앞뒤에 공백이 붙은 제목: 공백을 지운 제목으로 추가된다.
  - 이모지 "👍🏻" 하나: 1자로 센다.
- 목록이 항상 최신순으로 보인다. 완료한 항목도 마찬가지다.
- 체크박스를 누르면 완료 상태가 바로 바뀌고, 다시 누르면 원래대로 돌아온다.
- F-05: 각 버전에서 할 일을 추가, 완료 처리, 삭제한 뒤 새로고침하거나 서버를 껐다 켰을 때 "4. 버전별 데이터 유지" 표대로 동작한다.
- v0.3부터는 새로고침과 서버 재시작 뒤에도 결과가 그대로 남아 있다.
- 범위 밖 기능은 하나도 들어 있지 않다.

## 8. 결정이 필요한 것
- **v0.1의 데이터 유지**: v0.1에서 localStorage를 써서 새로고침해도 데이터가 남게 할지 정해야 한다. 정하면 "4. 버전별 데이터 유지" 표의 v0.1 줄을 채운다.
- **MVP 완성 시점**: F-05를 완전히 지키는 것은 v0.3(DB 저장)부터다. MVP가 완성되었다고 보는 버전을 v0.3으로 할지 정해야 한다.
- **삭제 확인**: 삭제 전에 "정말 지울까요?" 확인 창을 띄울지 정해야 한다.
- **배포 후 접근 제한**: 배포한 뒤 다른 사람이 들어오지 못하게 하는 방법을 정해야 한다. 로그인은 범위 밖이므로 다른 방법이 필요하다.

## 9. 결정된 것 (2026-10-23)
- **제목 검사 기준**: 앞뒤 공백을 지운 뒤 길이를 센다. 글자 수는 눈에 보이는 글자 하나를 1자로 센다. (한글 "가" = 1자, 이모지 "👍🏻" = 1자) 저장할 때도 공백을 지운 제목을 저장한다.
- **완료한 항목의 위치**: 완료 여부와 상관없이 최신순 그대로 둔다.
