## 2. 배운 점

- **"~를 바탕으로"라고 기준 문서를 적으면** AI가 문서끼리 내용을 맞춰서 쓴다.
- **"아직 실행하지 마", "테스트 코드는 아직 쓰지 마"처럼 범위를 정해 주면** 원하는 데까지만 진행한다.
- **큰 작업 전에 "결정할 사항이 있으면 알려줘"라고 물으면** 나중에 문서를 다시 고치는 일이 줄어든다. (5번)
- **기술을 바꿀 때는 "관련 문서를 모두 수정해줘"라고 하면** 여러 문서를 한 번에 맞출 수 있다. 바꾼 뒤에는 "확인해줘"로 한 번 더 점검한다. (19, 20번)
- **계획에 커밋 단계가 있으면 "진행해줘"만으로도 커밋될 수 있다.** 커밋은 따로 요청한다. (13, 14번)
- **"되돌려줘"는 무엇을 되돌릴지 분명히 적는다.** 이미 푸시한 커밋을 지우는 것은 강제 푸시가 필요해서 막힐 수 있다. (15번)

1. `v0.1을 시작하기 전에 반드시 결정할 사항이 있으면 알려줘` (localStorage 사용 여부, 삭제 확인 창 등)
2. `COMPONENT_SPEC.md와 DATA_MODEL.md를 바탕으로 src/types/todo.ts와 Zod 스키마(src/lib/validation/todo.ts)를 만들고, TEST_CASES의 API-01~12 케이스를 Jest 테스트로 작성해줘`
3. `TEST_CASES의 UI-01~14 케이스를 먼저 테스트로 작성하고, 그 테스트를 통과하도록 TodoForm을 만들어줘`
4. `같은 방식으로 TodoItem → TodoList → TodoApp 순서로 진행해줘. v0.1이므로 TodoApp은 API 없이 useState만 써줘`

### v0.2 API 연결 (FastAPI + 서버 메모리)
1. `TRD.md를 바탕으로 backend 폴더 초기 설정 계획을 세워줘. 가상환경, 설치할 패키지(requirements.txt), 만들 폴더, .gitignore에 추가할 항목을 목록으로만 보여주고 아직 실행하지 마`
